EXPERIMENT 1
Aim: Write a Program in Java to implement RPC
Theory
Remote Procedure Call (RPC) is a communication model in which a program on one machine (the client) calls a procedure that executes on another machine (the server) as if it were a local call. The programmer does not write explicit network code for each call; the details are hidden inside two pieces of code called stubs.
The client stub packs (marshals) the procedure name and its parameters into a message and sends it over the network. The server stub receives the message, unpacks (unmarshals) the parameters, calls the actual procedure and sends the result back. The client stub unmarshals the reply and returns it to the caller. In this experiment the RPC mechanism is implemented using Java TCP sockets together with DataInputStream and DataOutputStream for marshalling.
Tools Required
•	Java Development Kit (JDK 8 or higher)
•	Any text editor / IDE (Eclipse, IntelliJ IDEA, VS Code) or the command prompt
Procedure
1.	Create a folder and save RPCServer.java and RPCClient.java in it.
2.	Open a command prompt in the folder and compile both files: javac RPCServer.java RPCClient.java
3.	In the first command prompt start the server: java RPCServer. It waits on port 5000 for a client.
4.	In a second command prompt start the client: java RPCClient.
5.	The client calls add(), multiply() and factorial() remotely, and the server executes them and returns the results.
RPCServer.java
import java.io.*;
import java.net.*;
import java.util.Arrays;

public class RPCServer {
    // Remote procedures
    static long add(int a, int b)      { return a + b; }
    static long multiply(int a, int b) { return (long) a * b; }
    static long factorial(int n) {
        long f = 1;
        for (int i = 2; i <= n; i++) f *= i;
        return f;
    }

    public static void main(String[] args) throws Exception {
        ServerSocket server = new ServerSocket(5000);
        System.out.println("RPC Server started on port 5000. Waiting for client...");
        Socket socket = server.accept();
        System.out.println("Client connected: "
                + socket.getInetAddress().getHostAddress());

        DataInputStream in = new DataInputStream(socket.getInputStream());
        DataOutputStream out = new DataOutputStream(socket.getOutputStream());

        while (true) {
            String proc = in.readUTF();                 // procedure name
            if (proc.equals("exit")) break;
            int argc = in.readInt();                    // number of parameters
            int[] params = new int[argc];
            for (int i = 0; i < argc; i++) params[i] = in.readInt();
            System.out.println("Request received : " + proc
                    + Arrays.toString(params));

            long result;
            switch (proc) {
                case "add":       result = add(params[0], params[1]);      break;
                case "multiply":  result = multiply(params[0], params[1]); break;
                case "factorial": result = factorial(params[0]);           break;
                default:          result = -1;
            }
            out.writeLong(result);                      // send result back
            out.flush();
            System.out.println("Result sent     : " + result);
        }
        System.out.println("Client disconnected. Server stopped.");
        socket.close();
        server.close();
    }
}
RPCClient.java
import java.io.*;
import java.net.*;

public class RPCClient {
    static DataInputStream in;
    static DataOutputStream out;

    // Client stub: marshals the call, sends it and unmarshals the result
    static long call(String proc, int... params) throws IOException {
        out.writeUTF(proc);
        out.writeInt(params.length);
        for (int p : params) out.writeInt(p);
        out.flush();
        return in.readLong();
    }

    public static void main(String[] args) throws Exception {
        Socket socket = new Socket("localhost", 5000);
        in = new DataInputStream(socket.getInputStream());
        out = new DataOutputStream(socket.getOutputStream());
        System.out.println("Connected to RPC server.");

        System.out.println("add(10, 20)     = " + call("add", 10, 20));
        System.out.println("multiply(6, 7)  = " + call("multiply", 6, 7));
        System.out.println("factorial(10)   = " + call("factorial", 10));

        out.writeUTF("exit");
        out.flush();
        socket.close();
    }
}

EXPERIMENT 2
Aim: Implement the concept of Remote Method Invocation in Java.
Theory
Remote Method Invocation (RMI) is the Java API for object-oriented remote calls. It allows an object running in one Java Virtual Machine to invoke methods on an object running in another JVM. Unlike plain RPC, RMI works with objects: parameters and return values can be Java objects that are serialised automatically.
An RMI application has the following parts:
•	Remote interface – declares the methods that can be called remotely; it extends java.rmi.Remote and every method throws RemoteException.
•	Remote object (implementation) – implements the interface and extends UnicastRemoteObject so that it is exported to receive calls.
•	RMI registry – a naming service on which the server binds the remote object under a name and where the client looks it up.
•	Server – creates the remote object and binds it in the registry.
•	Client – looks up the remote object and calls its methods through the stub.
Tools Required
•	Java Development Kit (JDK 8 or higher)
•	Command prompt / terminal (two windows: one for the server and one for the client)
Procedure
1.	Save Calculator.java, CalculatorImpl.java, RMIServer.java and RMIClient.java in one folder.
2.	Compile all the files: javac *.java
3.	In the first window start the server: java RMIServer. It creates the registry on port 1099 and binds CalculatorService.
4.	In the second window run the client: java RMIClient.
5.	The client looks up CalculatorService in the registry and invokes add, subtract, multiply and divide on the remote object.
Calculator.java (remote interface)
import java.rmi.Remote;
import java.rmi.RemoteException;

// Remote interface: every remote method must throw RemoteException
public interface Calculator extends Remote {
    int add(int a, int b) throws RemoteException;
    int subtract(int a, int b) throws RemoteException;
    int multiply(int a, int b) throws RemoteException;
    double divide(int a, int b) throws RemoteException;
}
CalculatorImpl.java (remote object)
import java.rmi.RemoteException;
import java.rmi.server.UnicastRemoteObject;

// Remote object: implements the interface and is exported by UnicastRemoteObject
public class CalculatorImpl extends UnicastRemoteObject implements Calculator {
    public CalculatorImpl() throws RemoteException { super(); }

    public int add(int a, int b) {
        System.out.println("add(" + a + ", " + b + ") called");
        return a + b;
    }

    public int subtract(int a, int b) {
        System.out.println("subtract(" + a + ", " + b + ") called");
        return a - b;
    }

    public int multiply(int a, int b) {
        System.out.println("multiply(" + a + ", " + b + ") called");
        return a * b;
    }
    public double divide(int a, int b) {
        System.out.println("divide(" + a + ", " + b + ") called");
        return (double) a / b;
    }
}

}

EXPERIMENT 3
Aim: Write a java program to implement Lamport’s Logical clock
Theory
In a distributed system there is no global clock, so events on different machines cannot be ordered using physical time. Lamport’s logical clock gives a way to order events using the “happened-before” relation (→):
•	If a and b are events in the same process and a occurs before b, then a → b.
•	If a is the sending of a message and b is the receipt of that message, then a → b.
•	If a → b and b → c, then a → c (transitivity).
Every process Pi keeps a counter Ci (its logical clock) and follows two rules:
•	Rule 1: Ci is incremented by 1 before each event (internal event or send event) in process Pi.
•	Rule 2: When Pj receives a message with timestamp ts, it sets Cj = max(Cj, ts) + 1 before delivering the message.
If a → b then C(a) < C(b); the reverse is not necessarily true.
Tools Required
•	Java Development Kit (JDK 8 or higher)
Procedure
1.	Create the class Process with an id and a logical clock initialised to 0. For an internal event increment the clock; for a send event increment the clock and attach it to the message as the timestamp.
2.	For a receive event set the clock to max(local clock, message timestamp) + 1.
3.	Simulate three processes P1, P2 and P3 exchanging the messages m1 (P1 to P2), m2 (P2 to P3) and m3 (P3 to P1). Compile and run: javac LamportClock.java then java LamportClock
LamportClock.java
public class LamportClock {

    static class Process {
        int id;
        int clock = 0;
        Process(int id) { this.id = id; }

        // Rule 1: increment the clock before every event
        void internalEvent(String name) {
            clock++;
            System.out.printf("P%d: internal event %s -> clock = %d%n",
                    id, name, clock);
        }

        // Send event: increment clock, attach the timestamp to the message
        int send(int to, String msg) {
            clock++;
            System.out.printf(
                    "P%d: sends %s to P%d (ts = %d) -> clock = %d%n",
                    id, msg, to, clock, clock);
            return clock;
        }

        // Rule 2: on receive, clock = max(local clock, message timestamp) + 1
        void receive(int from, String msg, int ts) {
            int old = clock;
            clock = Math.max(clock, ts) + 1;
            System.out.printf(
                    "P%d: receives %s from P%d (ts = %d) -> max(%d, %d) + 1 = %d%n",
                    id, msg, from, ts, old, ts, clock);
        }
    }

    public static void main(String[] args) {
        Process p1 = new Process(1), p2 = new Process(2), p3 = new Process(3);

        System.out.println("=== Lamport's Logical Clock Simulation ===");
        p1.internalEvent("a");
        int t1 = p1.send(2, "m1");
        p2.internalEvent("b");
        p2.receive(1, "m1", t1);
        p3.internalEvent("c");
        p3.internalEvent("d");
        int t2 = p2.send(3, "m2");
        p3.receive(2, "m2", t2);
        int t3 = p3.send(1, "m3");
        p1.internalEvent("e");
        p1.receive(3, "m3", t3);

        System.out.println("\n=== Final logical clock values ===");
        System.out.println("P1 = " + p1.clock);
        System.out.println("P2 = " + p2.clock);
        System.out.println("P3 = " + p3.clock);
    }
}
Output

P1: internal event a -> clock = 1
P1: sends m1 to P2 (ts = 2) -> clock = 2
P2: internal event b -> clock = 1
P2: receives m1 from P1 (ts = 2) -> max(1, 2) + 1 = 3

EXPERIMENT 4
Aim: Implement mutual exclusion service using Lamport’s Mutual Exclusion Algorithm
Theory
Lamport’s algorithm is a permission-based algorithm that guarantees mutual exclusion in a distributed system without a central coordinator. It uses logical clocks to give every request a timestamp, so that requests are served in the order in which they were made. Each process keeps a request queue ordered by (timestamp, process id); the process id is used to break ties. Message channels are assumed to be FIFO.
The algorithm works in the following steps:
1.	To enter the critical section (CS), process Pi increments its clock, puts REQUEST(ts, i) in its own queue and sends REQUEST(ts, i) to all other processes.
2.	When Pj receives REQUEST(ts, i), it puts the request in its queue and sends a REPLY message to Pi.
3.	Pi enters the CS when (a) it has received a REPLY from every other process and (b) its own request is at the head of its queue.
4.	On leaving the CS, Pi removes its request from its queue and sends a RELEASE message to all other processes, which then remove Pi’s request from their queues.
For N processes, each CS entry needs 3(N − 1) messages: (N − 1) REQUEST, (N − 1) REPLY and (N − 1) RELEASE.
Tools Required
•	Java Development Kit (JDK 8 or higher; the program uses a record, so JDK 16 or higher is needed)
Procedure
1.	Create a Node class holding the logical clock, a priority queue of requests and the set of replies received.
2.	Implement requestCS() to broadcast REQUEST, and onMessage() to handle REQUEST, REPLY and RELEASE messages as described above.
3.	Implement tryEnter(), which lets a node enter the CS only if its request is at the head of the queue and a REPLY was received from all other nodes.
4.	In main(), create three processes P0, P1 and P2. Let P0 and P1 request the CS at the same time and deliver the messages through a FIFO queue that represents the network.
5.	Compile and run: javac LamportMutex.java then java LamportMutex
LamportMutex.java
import java.util.*;

public class LamportMutex {

    // Message exchanged between processes
    record Msg(String type, int from, int to, int ts) {}

    static Queue<Msg> network = new LinkedList<>();     // FIFO channel
    static Node[] nodes;

    static class Node {
        int id, n, clock = 0, reqTs = -1;
        boolean wantsCS = false;
        Set<Integer> replies = new HashSet<>();
        // request queue ordered by (timestamp, process id)
        PriorityQueue<int[]> queue = new PriorityQueue<>(
                (a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]);

        Node(int id, int n) { this.id = id; this.n = n; }

        void send(String type, int to) {
            network.add(new Msg(type, id, to, clock));
        }

        // Step 1: broadcast REQUEST(ts, id) and put it in own queue
        void requestCS() {
            clock++;
            reqTs = clock;
            wantsCS = true;
            replies.clear();
            queue.add(new int[]{reqTs, id});
            System.out.printf("P%d requests CS            [ts=%d]%n", id, reqTs);
            for (int j = 0; j < n; j++) if (j != id) send("REQUEST", j);
        }

        void onMessage(Msg m) {
            clock = Math.max(clock, m.ts) + 1;
            switch (m.type) {
                // Step 2: queue it and send REPLY
                case "REQUEST" -> {
                    queue.add(new int[]{m.ts, m.from});
                    clock++;
                    System.out.printf(
                            "P%d got REQUEST from P%d [ts=%d] -> sends REPLY%n",
                            id, m.from, m.ts);
                    send("REPLY", m.from);
                }
                case "REPLY" -> {
                    replies.add(m.from);
                    System.out.printf("P%d got REPLY   from P%d%n", id, m.from);
                }
                // Step 4: remove sender's request
                case "RELEASE" -> {
                    queue.removeIf(r -> r[1] == m.from);
                    System.out.printf(
                            "P%d got RELEASE from P%d -> removes request%n",
                            id, m.from);
                }
            }
            tryEnter();
        }

        // Step 3: enter CS if own request is first in the queue and
        // REPLY has been received from all other processes
        void tryEnter() {
            if (wantsCS && replies.size() == n - 1 && queue.peek()[1] == id) {
                System.out.printf(">>> P%d ENTERS critical section%n", id);
                System.out.printf("    P%d is executing in critical section...%n",
                        id);
                System.out.printf("<<< P%d EXITS critical section%n", id);
                wantsCS = false;
                queue.removeIf(r -> r[1] == id);
                clock++;
                for (int j = 0; j < n; j++) if (j != id) send("RELEASE", j);
            }
        }
    }

    public static void main(String[] args) {
        int n = 3;
        nodes = new Node[n];
        for (int i = 0; i < n; i++) nodes[i] = new Node(i, n);

        System.out.println("=== Lamport's Mutual Exclusion (3 processes) ===");
        nodes[0].requestCS();      // P0 and P1 request the CS at the same time
        nodes[1].requestCS();

        while (!network.isEmpty()) {
            Msg m = network.poll();
            nodes[m.to()].onMessage(m);
        }
        System.out.println("=== All requests served ===");
    }
}
Output

Result: Mutual exclusion was implemented using Lamport’s algorithm. Only one process was in the critical section at any time and the requests were served in timestamp order.

EXPERIMENT 6
Aim: Run a simple application on single node Hadoop Cluster
Theory
MapReduce is the processing model of Hadoop. A job is divided into a map phase and a reduce phase. The mapper reads the input split line by line and emits intermediate (key, value) pairs. The framework then shuffles and sorts these pairs by key and gives all the values of one key to a reducer, which combines them into the final output.
WordCount is the standard first MapReduce application. The mapper emits (word, 1) for every word in the input, and the reducer adds the values for each word to give the number of times it occurs. The input and output of the job are stored in HDFS, and the output folder must not already exist.
Tools Required
•	Hadoop 3.3.x running in single-node mode (Experiment 5)
•	JDK 8 or higher
•	WordCount.java and a sample input file input.txt
Procedure
1.	Start HDFS and YARN with start-dfs.cmd and start-yarn.cmd and check the daemons with jps.

WordCount.java
import java.io.IOException;
import java.util.StringTokenizer;

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class WordCount {

    // Map: emits (word, 1) for every word in the input line
    public static class TokenizerMapper
            extends Mapper<Object, Text, Text, IntWritable> {
        private final static IntWritable one = new IntWritable(1);
        private Text word = new Text();

        public void map(Object key, Text value, Context context)
                throws IOException, InterruptedException {
            StringTokenizer itr = new StringTokenizer(value.toString());
            while (itr.hasMoreTokens()) {
                word.set(itr.nextToken());
                context.write(word, one);
            }
        }
    }

    // Reduce: adds up all the 1s received for a word
    public static class IntSumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {
        private IntWritable result = new IntWritable();

        public void reduce(Text key, Iterable<IntWritable> values, Context context)
                throws IOException, InterruptedException {
            int sum = 0;
            for (IntWritable val : values) sum += val.get();
            result.set(sum);
            context.write(key, result);
        }
    }

    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "word count");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setCombinerClass(IntSumReducer.class);
        job.setReducerClass(IntSumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

EXPERIMENT 10
Aim: Simulate a cloud scenario using CloudSim and run a scheduling algorithm
Theory
CloudSim is a Java-based simulation toolkit for modelling cloud computing environments and testing resource-allocation and scheduling policies without needing a real cloud. Its main entities are:
•	Datacenter – the resource provider; it contains a list of hosts.
•	Host – a physical machine with processing elements (Pe, measured in MIPS), RAM and bandwidth.
•	Vm – a virtual machine created on a host.
•	Cloudlet – a task (job) whose size is given in million instructions (MI).
•	DatacenterBroker – acts on behalf of the user: it creates the VMs and submits the cloudlets.
Scheduling happens at two levels: the VmScheduler decides how the host’s processors are shared among VMs, and the CloudletScheduler decides how a VM’s processor is shared among its cloudlets. With CloudletSchedulerSpaceShared a VM runs one cloudlet at a time in the order in which they were received, so the order of submission decides the schedule. The following algorithms are compared:
•	FCFS (First Come First Served) – cloudlets are submitted in their order of arrival.
•	SJF (Shortest Job First) – the cloudlets are sorted by length and the shortest one is submitted first, which usually reduces the average completion time.
Tools Required
•	JDK 8 or higher
•	CloudSim 3.0.3 (cloudsim-3.0.3.zip from the CloudSim GitHub releases page; the jar is in the jars folder)
•	Eclipse IDE for Java (or the command prompt)
Procedure
1.	Download cloudsim-3.0.3.zip and extract it. The file jars\cloudsim-3.0.3.jar is the CloudSim library.
2.	In Eclipse create a new Java Project, then add cloudsim-3.0.3.jar through Project > Properties > Java Build Path > Libraries > Add External JARs.
3.	Create the class SchedulingDemo in the project and type the program given below.
4.	The program initialises CloudSim, creates one datacenter with two hosts (2 processing elements of 1000 MIPS each), a broker, two VMs of 1000 MIPS with space-shared cloudlet scheduling, and six cloudlets of different lengths.
5.	Run the program with the program argument FCFS (Run > Run Configurations > Arguments), and then again with the argument SJF.
6.	To run from the command prompt instead: javac -cp cloudsim-3.0.3.jar SchedulingDemo.java and then java -cp .;cloudsim-3.0.3.jar SchedulingDemo FCFS (use SJF for the second run).
7.	Compare the start time, finish time, average completion time and makespan of both the algorithms.
SchedulingDemo.java
import java.text.DecimalFormat;
import java.util.*;

import org.cloudbus.cloudsim.*;
import org.cloudbus.cloudsim.core.CloudSim;
import org.cloudbus.cloudsim.provisioners.*;

/**
 * CloudSim scheduling demo.
 * Usage: java SchedulingDemo FCFS   |   java SchedulingDemo SJF
 * FCFS : cloudlets are submitted to the broker in arrival order
 * SJF  : cloudlets are sorted by length (shortest job first) before submission
 */
public class SchedulingDemo {

    public static void main(String[] args) throws Exception {
        String algo = args.length > 0 ? args[0].toUpperCase() : "FCFS";
        // keep CloudSim's own log quiet
        Log.disable();

        // Step 1: initialise the CloudSim package
        CloudSim.init(1, Calendar.getInstance(), false);

        // Step 2: create a datacenter with two hosts
        Datacenter datacenter = createDatacenter("Datacenter_0");

        // Step 3: create a broker
        DatacenterBroker broker = new DatacenterBroker("Broker_0");
        int brokerId = broker.getId();

        // Step 4: create 2 VMs (1000 MIPS each, space-shared scheduling)
        List<Vm> vmList = new ArrayList<>();
        for (int i = 0; i < 2; i++)
            vmList.add(new Vm(i, brokerId, 1000, 1, 512, 1000, 10000, "Xen",
                    new CloudletSchedulerSpaceShared()));
        broker.submitVmList(vmList);

        // Step 5: create 6 cloudlets of different length (MI)
        long[] length = {40000, 10000, 30000, 20000, 50000, 15000};
        List<Cloudlet> cloudletList = new ArrayList<>();
        UtilizationModel full = new UtilizationModelFull();
        for (int i = 0; i < length.length; i++) {
            Cloudlet c = new Cloudlet(i, length[i], 1, 300, 300, full, full, full);
            c.setUserId(brokerId);
            cloudletList.add(c);
        }

        // Step 6: apply the scheduling algorithm
        if (algo.equals("SJF"))
            cloudletList.sort(Comparator.comparingLong(Cloudlet::getCloudletLength));
        broker.submitCloudletList(cloudletList);

        // Step 7: run the simulation
        CloudSim.startSimulation();
        List<Cloudlet> result = broker.getCloudletReceivedList();
        CloudSim.stopSimulation();

        printResult(result, algo);
    }

    private static Datacenter createDatacenter(String name) throws Exception {
        List<Host> hostList = new ArrayList<>();
        for (int h = 0; h < 2; h++) {
            List<Pe> peList = new ArrayList<>();
            peList.add(new Pe(0, new PeProvisionerSimple(1000)));
            peList.add(new Pe(1, new PeProvisionerSimple(1000)));
            hostList.add(new Host(h, new RamProvisionerSimple(2048),
                    new BwProvisionerSimple(10000), 1000000, peList,
                    new VmSchedulerTimeShared(peList)));
        }
        DatacenterCharacteristics ch = new DatacenterCharacteristics(
                "x86", "Linux", "Xen", hostList, 10.0, 3.0, 0.05, 0.001, 0.0);
        return new Datacenter(name, ch, new VmAllocationPolicySimple(hostList),
                new LinkedList<Storage>(), 0);
    }

    private static void printResult(List<Cloudlet> list, String algo) {
        list.sort(Comparator.comparingDouble(Cloudlet::getFinishTime));
        DecimalFormat df = new DecimalFormat("0.00");
        double total = 0, makespan = 0;
        System.out.println("Scheduling algorithm : " + algo);
        System.out.println("========== OUTPUT ==========");
        System.out.println("Cloudlet  Status   VM  Length(MI)  Start   Finish");
        for (Cloudlet c : list) {
            System.out.printf("%-9d %-8s %-3d %-11d %-7s %s%n", c.getCloudletId(),
                    c.getCloudletStatus() == Cloudlet.SUCCESS ? "SUCCESS" : "FAILED",
                    c.getVmId(), c.getCloudletLength(),
                    df.format(c.getExecStartTime()), df.format(c.getFinishTime()));
            total += c.getFinishTime();
            makespan = Math.max(makespan, c.getFinishTime());
        }
        System.out.println("Average completion time : "
                + df.format(total / list.size()) + " sec");
        System.out.println("Makespan                : "
                + df.format(makespan) + " sec");
    }
}
